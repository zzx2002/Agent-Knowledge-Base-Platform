# 数据库设计

数据库：PostgreSQL 16。初始化脚本：`backend/knowledge-api/src/main/resources/db/migration/V1__init.sql`，逻辑删除迁移：`V2__add_logical_delete.sql`，解析结果字段迁移：`V3__add_parse_result_fields.sql`，任务错误码迁移：`V4__add_task_error_code.sql`，索引字段迁移：`V5__add_chunk_index_fields.sql`。

## 逻辑删除约定

- 所有业务表都有 `deleted BOOLEAN NOT NULL DEFAULT FALSE` 字段，MyBatis-Plus 实体通过 `@TableLogic` 自动过滤与软删除。
- 删除知识库/文档时，级联把关联的版本、元素、分块、解析任务一并标记为 `deleted=TRUE`。
- 用户名、角色编码等唯一约束改为**仅未删除记录唯一**的部分唯一索引，逻辑删除后可用同名重新创建。
- 例外（允许物理删除）：
  - `kb_permission` 授权记录在撤销/删除知识库时直接 `DELETE`；
  - MinIO 中的原始文件对象在删除文档时直接移除。

## 存储职责边界

- PostgreSQL：用户信息、知识库、文档元数据、任务状态、权限、Agent 配置。
- MinIO：原始文件、格式转换文件、解析产物、图片资源。
- Elasticsearch：文档与分块的全文索引，BM25 检索。
- Qdrant：分块向量及过滤元数据。
- Redis：缓存、临时任务状态、限流、分布式协调。

## 解析结果字段（V3）

- `kb_document_element`：新增 `version_id`、`parse_task_id`，用于区分重新解析产生的不同版本结果。
- `kb_chunk`：新增 `version_id`、`parse_task_id`、`element_ids`，记录分块版本、来源任务与元素列表；V5 增加 `es_id`、`qdrant_point_id`、`indexed_at`、`index_error` 记录外部索引状态。
- `kb_parse_task`：新增 `result_key`、`result_summary`，保存 MinIO 解析结果对象键与统计摘要；V4 增加 `error_code` 保存标准化错误码。
- 重新解析时先逻辑删除旧版本元素与分块，再写入新版本，保证预览接口只返回当前有效结果。

## 变更规范

修改表结构时：新增迁移脚本（如 `V6__xxx.sql`），不要修改已发布的 V1/V2/V3/V4/V5；同步更新实体类与本文。
