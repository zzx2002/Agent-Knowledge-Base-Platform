# REST API

统一前缀：`/api/v1`。除登录外均需 `Authorization: Bearer <token>`。统一响应结构：`{ "code": 0, "message": "ok", "data": ... }`。

## 认证

| Method | Path | 说明 |
| --- | --- | --- |
| POST | /auth/login | 账号密码登录 |
| POST | /auth/logout | 退出 |
| POST | /auth/refresh | 刷新 Token |
| GET | /auth/me | 当前用户 |

## 用户管理（仅 ADMIN）

| Method | Path | 说明 |
| --- | --- | --- |
| POST | /users | 创建用户并分配角色 |
| GET | /users | 用户列表 |

创建用户请求体：

```json
{
  "username": "alice",
  "password": "password123",
  "display_name": "Alice",
  "role_code": "EDITOR"
}
```

角色：`ADMIN` / `KB_ADMIN` / `EDITOR` / `VIEWER`。可用不同账号登录验证知识库隔离。

## 知识库

| Method | Path | 说明 |
| --- | --- | --- |
| POST | /knowledge-bases | 创建（自动归属当前用户） |
| GET | /knowledge-bases | 列表（仅返回有权访问的知识库） |
| GET | /knowledge-bases/{id} | 详情 |
| PUT | /knowledge-bases/{id} | 更新 |
| DELETE | /knowledge-bases/{id} | 删除 |
| GET | /knowledge-bases/{id}/permissions | 授权列表 |
| POST | /knowledge-bases/{id}/permissions | 授权用户/角色 |
| DELETE | /knowledge-bases/{id}/permissions/{subjectType}/{subjectId}/{permission} | 撤销授权 |

授权请求体：

```json
{ "subject_type": "USER", "subject_id": 2, "permission": "READ", "granted": true }
```

`subject_type` 支持 `USER` / `ROLE`；`permission` 支持 `READ` / `WRITE` / `DELETE` / `ADMIN`。只有知识库 owner 或全局管理员可管理授权。

## 数据隔离规则

- 创建知识库时自动写入 `owner_id = 当前登录用户`。
- `ADMIN` / `KB_ADMIN` 角色可访问全部知识库。
- 知识库 owner 对自己的库拥有全部权限。
- 其他用户只能访问 `kb_permission` 中显式授权且 `granted=true` 的知识库与操作。
- 知识库列表、文档列表、任务列表均在服务端按上述规则过滤；越权访问返回 403。

## 检索与问答

| Method | Path | 说明 |
| --- | --- | --- |
| POST | /search | 混合检索 |
| GET | /search/debug | 检索调试 |
| POST | /chat | RAG 问答 |
| POST | /chat/stream | 流式问答（SSE） |

检索请求示例：

```json
{
  "knowledgeBaseId": "2123289000128622594",
  "query": "解析服务如何回传结果",
  "topK": 5,
  "rerank": true
}
```

检索响应示例：

```json
{
  "code": 200,
  "data": {
    "query": "解析服务如何回传结果",
    "hits": [
      {
        "chunkId": "2123296372205740033",
        "documentId": "2123296369978564609",
        "fileName": "test_parse.txt",
        "content": "平台采用业务服务、解析服务与模型服务分离的架构...",

        "vectorScore": 0.0366,
        "rerankScore": 0.0222
```

## 解析任务消息

Java API 投递到 RabbitMQ `kb.parse.queue` 的消息字段（snake_case）：

```json
{
  "task_id": 1,
  "document_id": 1,
  "knowledge_base_id": 1,
  "storage_key": "documents/1/uuid_file.docx",
  "file_name": "file.docx",
  "file_type": "DOCX",
  "attempt": 1,
  "chunk_config": { "chunk_size": 800, "chunk_overlap": 100 }
}
```

Worker 完成解析后把完整结果写入 MinIO `parse-results/{task_id}/{attempt}.json`，回调只传结果引用与统计：

```json
{
  "task_id": 1,
  "status": "COMPLETED",
  "progress": 100,
  "message": "解析完成",
  "result_key": "parse-results/1/1.json",
  "result_summary": { "element_count": 12, "chunk_count": 6, "elapsed_ms": 860 }
}
```

失败回调示例：

```json
{
  "task_id": 1,
  "status": "FAILED",
  "progress": 42,
  "message": "OCR 引擎连接超时",
  "error_code": "OCR_FAILED",
  "timestamp": 1763529700
}
```

Python Worker 从 MinIO 下载 `storage_key` 对应对象，解析、清洗、分块后回调 knowledge-api；knowledge-api 再根据 `result_key` 下载解析结果并落库元素与分块。
